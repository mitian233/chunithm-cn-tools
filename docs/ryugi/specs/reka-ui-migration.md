# Naive UI 迁移规划

在 `ui-optimization` 分支分五步迁移。保留页面结构、路由、搜索和计算行为，用 Reka UI 提供交互，用 Tailwind CSS 3 和项目自己的样式统一深浅色。简单布局使用原生 HTML。迁移期间新旧页面共用当前主题选择，每一步可以独立提交。

## M1 · 公共样式和首批页面

- 加入 Reka UI，在应用根部设定中文区域。用 `<html>` 上的 `data-theme` 和 CSS 变量统一背景、文字、边框、主色和难度颜色。沿用 `localStorage.darkMode`，让应用布局、旧组件和新页面同时切换。
- 在 `src/main.css` 建立卡片、按钮和标签样式。迁移主页、关于页和 404，保留主页入口、关于页内容及链接。
- 在桌面和手机宽度试用三个页面。切换主题时，新卡片与现有侧栏同步变化，刷新后仍是已选择的主题。

新页面复用 `src/main.css` 的 `.ui-card`、`.ui-button`、`.ui-tag` 和 `.ui-link`。颜色使用同一文件的 `--ui-*` 变量。`App.vue` 用同一个主题状态更新 `<html>` 和 Naive 的主题，Reka 组件统一使用 `zh-CN`。

## M2 · 歌曲、别名、称号和详情

- 用项目自己的表格保留歌曲表的四列排序、横向滚动、长文本提示和详情链接。歌曲表和别名表使用 TanStack Virtual，在 600px 高的滚动区域按需显示行，别名行按标签换行后的高度计算。称号表使用普通表格。保留各表的搜索、加载状态和无结果提示。
- 迁移歌曲详情的难度标签页、折叠区和封面，使用共用的图片预览。保留歌曲表的懒加载、详情的失败替代图和原有图片操作。入口从歌曲列表、别名列表和详情分别试用。

`CatalogTable.vue` 通过列配置和插槽渲染表格。歌曲表和别名表开启虚拟滚动，按记录 ID 跟踪行并测量实际高度，称号表直接显示全部匹配行。`CoverPreview.vue` 由歌曲列表和歌曲详情共用。

## M3 · 计算器和筛选控件

- 先做通一个可即时更新的 Rating 数字框，再迁移全部六个数字框、定数结果表、OP 和分数线计算。数字框清空后传 `null`，各页面沿用自己的取值范围和步长。保留 OP 满分自动选 AJC。
- 迁移难度多选、版本和类别选择，保留全选与清空。保留 Rating 标签页的输入状态，以及歌曲详情跳转后预填定数和连击数的行为。
- 在实际页面输入小数、清空、达到满分并切换标签页，确认结果和状态按原有方式更新。

## M4 · 全站导航和实验室

- 迁移应用布局、桌面可折叠侧栏和手机左侧抽屉。导航使用路由链接和当前页标记，手机抽屉用 Reka Dialog 实现。迁移公告与广告容器。
- 迁移实验室标签页和随机歌曲的单选、双滑块和类别下拉。试用模式切换、选项禁用、清空结果、公告关闭后刷新、桌面折叠及手机导航。

## M5 · 移除 Naive UI

- 移除模板标签、`h()` 调用、全局注册、四个未调用的 provider 和 `--n-*` 样式引用。从 `package.json` 移除 `naive-ui`，并确认重新安装后生成的锁文件中也没有它。
- 运行 `pnpm build`，在桌面和手机宽度下试用导航、搜索与排序、长列表、封面预览、计算器和深浅色切换。
